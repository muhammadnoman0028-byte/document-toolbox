# Contributing

## Guidelines

- Keep code and assets organized in the appropriate directories.
- Use clear, descriptive names for files, components, and functions.
- Document significant architectural or workflow changes in `docs/`.
- Add or update tests in `tests/` when introducing new behavior.

## Workflow (suggested)

1. Create a branch for your change.
2. Make focused, well-scoped commits.
3. Verify changes locally (lint/build/tests as available).
4. Open a pull request with a clear summary and context.
